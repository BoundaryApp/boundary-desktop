# Stack contract

Everything Boundary takes from the agent stack, where Boundary uses it, and which check covers it
([ADR 0031](adr/0031-checks-on-the-stack-contract-and-drift.md)). A dependency missing from this
table has no check. Moving the stack pin means reading the stack's changelog against it.

`test:stack` cases live in these files, among others:

- `hermesConfig.stack.test.ts` (keys, settings program) under `src/main/services/assistant/__tests__/`
- `stackHttp.stack.test.ts` (HTTP) in the same folder
- `hermesGateway.stack.test.ts` (catalog, live calls, the recovery notice) under `src/main/services/assistant/hermes/__tests__/`
- `workloadHold.stack.test.ts` (three real turns held to a limit of 1 against a fake model server on the Mac at `host.docker.internal`) in the same folder
- `addons.stack.test.ts` (the Twenty add-on's MCP server) in the same folder as `hermesConfig.stack.test.ts`
- `crmScript.stack.test.ts` (`crm.sh add` and `remove` against a local HTTP server; needs only the stack's checkout) in the same folder
- `sharedServiceWorkspace.stack.test.ts` (a Circle's shared Twenty workspace, written by Boundary, through the stack's own `instances-plan`; needs only the stack's checkout and `python3`) in the same folder
- `actualAddon.stack.test.ts` (connects and disconnects a budget on the stack's own Actual server; runs only with `BOUNDARY_STACK_WRITES=1`) in the same folder
- `bitwardenAddon.stack.test.ts` (connects and disconnects a Bitwarden account through the stack's real `addon.sh` and `vault.sh` in a temp copy with a stub broker; then, with `BITWARDEN_ENABLED=1` in the stack under test, finds `bitwarden_request_access` in a new chat) in the same folder
- `emailAddon.stack.test.ts` (reads `addon.sh list --json` and checks the `email` entry's `schema`; read-only, and it never passes the listing's account values to an assertion or message) in the same folder
- `vikunjaAddon.stack.test.ts` (reads `addon.sh list --json` and checks the `vikunja` entry's `hooks`, `web` and `data.schemas`; read-only, and it never opens the web app) in the same folder
- `builtinAddons.stack.test.ts` (reads `addon.sh list --json` and checks that the `n8n` and `lightrag` entries' `enabled` follows their `.env` flags and n8n's `data.volumes`; read-only) in the same folder
- `workerKey.stack.test.ts` (the SSH worker key's owner in the running `hermes`) in the same folder
- `detectorAddon.stack.test.ts` (the detector add-on's `/health`, a `too_short` refusal and a wrong token; costs nothing and sends nothing off the Mac; skipped unless the add-on is on with its token) in the same folder

The catalog case checks each gateway method, param, event and server request against Hermes's
contract registry (`tui_gateway.contracts`) in the running image. Names the stack's overlays add
at runtime are not in that registry; each of those has a live case instead.

## Running the suite

```sh
bun run test:stack
```

It needs a running stack and the `docker` CLI. By default it targets the `assistant` checkout beside
this repository on the default ports; `BOUNDARY_ASSISTANT_ROOT`, `BOUNDARY_STACK_PORTS=offset-ports`,
`BOUNDARY_STACK_CONTAINER` and `BOUNDARY_STACK_DOCKER` point it elsewhere. Credentials come from the
stack's own files, read by Boundary's resolvers. Each file skips, and says why, when the stack isn't
reachable. The settings-program case writes only to a temporary folder under the Hermes container's
`/tmp` and removes it. The suite logs in to the dashboard four times; the dashboard allows ten
password logins a minute per address.
