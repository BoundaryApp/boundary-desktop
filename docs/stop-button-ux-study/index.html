UX study · composer run control

Stop appears only while the agent is running

Today the composer always shows a Stop button at the right end of the cluster. Its cancel primitive disables it when idle, but it still reads as a live control. This study removes it and tries three placements where Stop shows up only during a run. The live mock is interactive: type and press Enter to start a fake run, then press Stop or Esc.

Chosen: A · Morph (1 Oct 2026). The implementation plan is spec.md.

One round button in the composer's bottom-right corner. It shows Send ↑ when idle and becomes Stop ■ during a run. ChatGPT, Claude, LM Studio and Open WebUI all use this pattern, so people already know where to look.

  • The corner always holds the one action that matters right now. The cluster (project, model, @, phase, Tools) stays put, with no layout shift as a run starts or ends.
  • A ring traces around the button while the agent works. When it waits for approval, the ring pauses and turns amber, so the button itself shows the agent is busy.
  • The composer adds a Send button, which it doesn't have today. That gives mouse users and new users a visible way to send, and Enter still works.

Placements

A · Chosen

Morph

Send and Stop are one button in the input's corner. It morphs on run start and run end.

+ Familiar from other chat apps, no layout shift, and it adds a Send affordance.
− A double-click on Send could hit Stop. The guard below covers this.
B · Smallest diff

Cluster

A Stop chip with an esc hint appears at the right of the cluster, next to the live phase line. When idle, a quiet "↵ send" hint sits there.

+ A near one-line change, and Stop sits beside the status it ends.
− Small target, and it sits low and away from the input's focus point.
C · Most visible

Pill

A floating "■ Stop · Generating…" pill over the bottom of the transcript, centered on the column. This is the older ChatGPT and Bionic style.

+ Hard to miss, and it carries the phase text.
− Covers the last lines of streaming text, and it is a second floating layer next to the quote and mention popovers.

Details that make it feel right

  1. Double-click guard. Ignore Stop for about 350 ms after the send that started the run, so a double-click on Send can't cancel the run on its second click.
  2. Same element, swapped label. Morph one button rather than mounting two, so keyboard focus survives the swap. Flip aria-label between "Send message" and "Stop response".
  3. Esc precedence. Esc first closes the mid-run menu, or an open mention or quote popover. Only when nothing is open does it stop the run. Today the composer uses Esc only for mentions (WorkbenchThread.tsx:707).
  4. Reduced motion. The ring and glyph crossfade turn off under prefers-reduced-motion. The glyph alone still carries the state.

What Hermes already supports (checked in hermes-agent v2026.9.14)

UI actionGateway callWhat the server does
Stopsession.interruptHard interrupt. Any text already streamed is saved to the session as an assistant message. It also clears Hermes's own queue and denies pending approvals.
Continueprompt.submit with display_kind: "hidden"There's no resume-the-same-generation call. Continue is a new turn that reads the saved partial, and the hidden kind keeps a "continue" bubble out of the transcript. It works. It just isn't token-exact.
Send nowprompt.submit while busyThe default busy_input_mode: interrupt redirects the live turn in place. The model sees "Visible response before the interruption" and then your message. Older agents and messages with attachments fall back to interrupt + queue.
Queueprompt.submit with queued: true, sent on drainHermes notes that queued: true is meant for "client queue drain", so it never becomes a live correction. There's no RPC to edit or remove a queued item, and Stop wipes the server's queue. So the queue lives in the desktop, and each item goes out with queued: true when the run ends.
Not mockedsession.steerA fourth option: inject the text after the agent's current step, without interrupting. It could become "Add to this run" later.

The stack doesn't set display.busy_input_mode, so Send now relies on Hermes's default. The bootstrap should pin it to interrupt, so a config change can't silently turn Send now into Queue. Details are in backend-notes.md.

Channels: decide the shape now, build it later

  1. This control is per agent. In a channel, the composer's Stop and the Enter menu act only on the agent(s) your last message addressed. Each Hermes member is its own session, so session.interrupt already works per agent.
  2. Stop all goes somewhere else: the channel header shows "■ Stop all · 3 running" only while two or more members are running. That keeps the composer corner meaning one thing everywhere.
  3. Each running reply also gets its own small Stop in its live phase line, so you can stop one member you didn't address.
  4. One thing is worth deciding now: make the queue per session, keyed by the agent the draft addresses. Then a channel's queue is just several per-agent queues, and Stop all can pause all of them using the same Paused state.

Open questions

  1. Should there be "Don't ask again: always queue" in the mid-run menu, backed by a setting? It would cut friction for people who always pick the same option.
  2. Should Send now (redirect) look different from Stop in the transcript? The mock says "Interrupted · you sent a new message" rather than "Stopped by you".
  3. Is "Add to this run" (session.steer) worth a fourth menu row, or is it too subtle a difference from Send now?
