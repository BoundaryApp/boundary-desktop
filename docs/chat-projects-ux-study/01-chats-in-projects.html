Chats belong to projects

A study for Boundary's chat workbench. Today a chat has no project of its own and adopts whichever project is active, so switching projects silently rewires the chat you're in. This proposal gives every conversation a home and makes changing that home a deliberate act.

A chat lives in one project, or in none

The project is set when the chat starts and stored on the chat. Its folder, sources and inference pin come from that project, every time.

The picker navigates

Choosing a project in the rail takes you to that project. It never changes the chat you were in. Opening a chat from another project switches the rail to follow it.

Move is the only way to re-file

Move to project… says what will change before it happens and leaves a line in the transcript. Undo is one click away.

DMs stay global

A DM is one ongoing thread per agent, so it can't live in one project. It has its own folder setting, and every change to it is logged in the thread.

How each kind of conversation behaves

  • Hermes chat lives in a project or in none. Breadcrumb, movable.
  • Channel lives in a project or in none. A room is a topic, and topics usually belong to a project. Movable.
  • Side chat starts in its parent's project. It's movable like a Hermes chat. A DM's side chat starts in the DM's current folder.
  • Direct message is global and always listed. It has a folder setting, logged when it changes.
  • Branch and Make channel keep the source chat's project.

Open questions

  • Telegram, WebUI and API chats arrive outside the app. Do they land in No project, or in a project set in Settings → Sources?
  • Removing a project: do its chats go to No project (proposed) or get archived with it?
  • Should Mentions follow the rail's project, or stay global like All chats (proposed)?
  • Should the chat's own inference override survive a move? Proposed: yes. It belongs to the chat, and Move warns when the effective model changes.
