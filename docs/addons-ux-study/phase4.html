What this mock covers

Phase 4 of the add-ons spec for Twenty: connecting a hosted workspace, the access choice, the owner password, moving from this Mac’s Twenty to a hosted one, and removal shown as steps. It builds on prototype.html, which stays as the record for phases 1 to 3.

Two ways in

Before anything is set up, Twenty’s page offers both paths side by side: run Twenty on this Mac, or connect one the user already has. Connecting starts no containers and needs no memory, so the fit check applies only to the first path. After either, the page lists workspaces, one row each, with the name agents use (crm-main, crm-work).

Changes that wait for a restart

Connecting, disconnecting, changing access and turning off all change which tools Hermes registers, and the pinned stack picks those up only when the assistant restarts. Instead of a dialog after each change, the page collects them in one bar with Restart assistant and Later. While agent work runs, the bar offers Restart when the task finishes, as the install’s last step does.

Access has two settings for now

Look things up gives agents the workspace’s read-only key; Make changes gives them the read-write key. Make changes after asking you is left out: Hermes v0.22.7 asks before an MCP call by tool name only, and every Twenty record call goes through execute_tool, so it would ask before every lookup too. A change request asks the stack for a way to ask before writes only. Unattended runs always get the read-only key, whatever the setting.

For this Mac’s workspace, the read-only description is what crm init’s role allows. For a hosted workspace it depends on the role the user gave the key, and the row says so.

Twenty opens signed in

The install asks for no email or password: crm init creates the owner owner@crm.localhost with a generated password. Open Twenty then skips Twenty’s sign-in page. Boundary asks the stack for a one-time login link to the workspace (crm.sh login-link), which signs in as the owner and returns <workspace URL>/verify?loginToken=…. Twenty’s web app exchanges the token for a session, and the browser stays signed in after that. Each click makes a new link, and a login token expires after 15 minutes by default, so a link left in browser history stops working.

A new step in the install, Setting up your profile, names the owner after this Mac account’s full name and skips Twenty’s welcome steps (profile, email sync, team invite), so the first open lands on the CRM rather than a welcome screen. Hosted workspaces keep their own sign-in.

Read from Twenty’s source on GitHub, whose newest tag is v2.9.0; the stack pins the image twentycrm/twenty:v2.55.0. The /verify route, the token lifetime and the welcome steps get checked against that image before this is built.

The owner password stays out of the agents’ vault

Passwords & Logins holds logins agents use in the browser. Twenty’s owner is a server admin, so storing it there would hand agents a login that bypasses the roles behind the access choice. The local row has Copy password instead, for another browser or device. Boundary’s main process reads it from the stack’s settings and puts it on the clipboard; the renderer never receives it.

Moving to a hosted workspace

When this Mac’s Twenty and a hosted workspace are both connected, the page shows three steps: connected, copy your records, turn this Mac’s Twenty off. The stack has no migration tool, so records move through Twenty’s own export and import. The copy for that step needs checking against Twenty v2.55 before it ships. Keep both hides the steps.

Turning off with a hosted workspace connected stops only the local containers. Agents keep the hosted workspace, and Boundary sets the local workspace file aside so Hermes doesn’t register crm-main against a stopped server.

Removal runs as steps

Today the confirmation sheet stays open with Deleting… until Turn off and the deletion both finish. Here the sheet closes as soon as the user confirms, and the page shows the same progress view as an install: overall bar, one row per step, a dot on the Services icon, and the user can leave. Steps when Twenty is on:

StepWhat happens
Stopping TwentyStops its four containers.
Removing its containersRemoves them, as Turn off does today.
Deleting its database and filesThe Twenty data folder: Postgres and attachments.
Removing the owner sign-in and agent keysThe local workspace file and the owner sign-in in the stack’s settings. Hosted workspaces stay.
Deleting the downloaded imagesOnly when the user ticks it in the confirmation. New: removal doesn’t delete images today.
Restart the assistantWaits for the user, as the install’s last step does. Skipped when Twenty was already off, because Turn off restarted it.

A failure shows the step’s log and offers Try again. There is no Undo: deleted data can’t come back, and the callout says what state Twenty is left in.
