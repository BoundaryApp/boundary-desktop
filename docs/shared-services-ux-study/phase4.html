Shared Twenty: click-through for phase 4 Viewing as Ada’s Mac

What this covers

Phase 4 of the shared services spec, for Twenty: sharing this Mac’s Twenty with a Circle from Twenty’s page, the shared row that follows, a member turning on Use in my agent for a workspace shared with them, and where a tool call says whose Twenty answered. ADR 0048 holds the decisions; this mock shows where they land.

One page for both sides

Twenty’s page already lists every workspace the agents can reach. A shared workspace is one more of them, so both sides live there: the provider’s share settings hang off On this Mac, and a member’s shared workspaces get their own group, From your Circles, below the hosted ones. A shared workspace a member uses isn’t listed again as hosted, though the stack stores it the same way.

Sharing

Share with a Circle… appears on On this Mac while Twenty runs. The sheet picks one Circle, what members may do by default, a choice per member that starts at that default, and whether to keep the Mac awake. Saving publishes the offer and mints keys for each member who gets access, named <member> · <Circle>. Members added to the Circle later get no access until the provider gives it; the row says how many have none.

Each Circle shared with gets a line under the row: who has which access, today’s calls per member, Change… and Stop sharing. Stop sharing takes the offer down and revokes every member’s keys.

Using

A member sees each offer in From your Circles, with the provider’s name, the Circle, and whether the provider is online now. Use in my agent is off until they turn it on, because each workspace adds tools to every turn and needs a restart. Turning it on adds a line to the restart bar, and the access switch works as it does for hosted workspaces. The provider’s grant still decides: a member who picks Make changes on a read grant gets a refusal on the first change, saying so.

Offline

Nothing is hidden while the provider is offline. The row says so, and a tool call answers with the provider’s name and that their Mac is offline. The chat shows it as a failed tool call, like any other.

Provenance

A tool call to a shared workspace says whose it is and through which Circle, under the tool’s name.

Not in this mock

  • The Circle’s Shared section. The Circle view’s layout is changing; the section follows that change, built from the same data as these rows.
  • Private and Trusted. The person panel already sets both for a provider’s models. For a service, Trusted would register the workspace as untrusted otherwise, and the stack’s instance store has no setting for that yet, so it needs a change request before it can apply.
  • Revoking when a member leaves, and sharing a hosted workspace (phase 5).
