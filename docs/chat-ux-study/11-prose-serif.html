Product designer with eight years shipping research-backed interfaces for hiring and ops tools. Recent work includes a job-search system that turns a local folder of resumes, notes, and applications into a single working set — scoped to files on disk, not an uploaded copy.

How to talk about the through-line

Keep the working set local, name the tools as they run, and leave the human in the loop when something dangerous is about to execute. The one-liner is: I design systems that stay on the person’s machine.

What the folder actually shows

The resume and cover-notes.md agree on three strengths. Use these in the first screen, not buried under a tools list:

  • Research that becomes a shipped surface, not a slide.
  • Local-first product sense — folders, mounts, and honest empty states.
  • Visual critique that asks before rewriting a whole deck.

Prefer a dedicated read-only notes folder. Never mount the home folder. The path stays visible so the person always knows what the agent can see.

If a hiring manager asks how the system is wired, walk the sequence — do not invent a cloud sync story:

  1. Choose a folder on disk and bind it.
  2. Index only what is mounted.
  3. Open files in the native manager, not a fake tree.
